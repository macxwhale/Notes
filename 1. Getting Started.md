# Getting Started with Safaricom Daraja APIs

## Overview
Safaricom Daraja APIs enable developers to integrate M-Pesa payment services into their applications. These APIs allow businesses to send and receive payments using M-Pesa services such as B2C, C2B, and B2B.

The APIs are RESTful, use HTTP methods (GET and POST), and exchange data using JSON for both requests and responses, including error handling.

---

## Introduction to Safaricom APIs
Safaricom focuses on building technologies that positively impact society by empowering innovators and partners. The Daraja platform provides access to M-Pesa services through secure and standardized APIs.

### Key Features
- Access to M-Pesa services: **B2C, C2B, and B2B**
- RESTful architecture
- JSON-encoded requests and responses
- HTTP status codes compliant with **RFC 2616**

  - Curl

## Terminologies

### M-Pesa
A mobile money service in Kenya that allows users to store and transfer money using mobile phones.

### Command IDs
Unique identifiers that specify the type of M-Pesa transaction being performed.

### Payment Types
- **Salary Payment**: Sends money to both registered and unregistered M-Pesa users.
- **Business Payment**: Sends money to registered M-Pesa users.
- **Promotion Payment**: Sends promotional payments with congratulatory messages to registered users.

### Short Codes
Unique numbers used to receive payments:
- **Pay Bill**: For recurring customer payments
- **Buy Goods**: For retail purchases
- **Till Number**: Linked to a physical or online store

### REST
An architectural style used for designing networked applications.

### APIs
Interfaces that allow applications to access services or data.

### DOCS
Technical documentation for API usage and integration.

## Testing on Localhost
Since M-Pesa APIs require publicly accessible callback URLs, local testing must be done using HTTP tunneling tools such as:
- **Ngrok**
- **LocalTunnel**

These tools expose local servers to the internet for callback handling.

## Going Live (Production Setup)

Before moving to production, ensure the following:

- You have an active **M-Pesa account** (PayBill, Till Number, or B2C)
- You have access to the **M-Pesa Portal**
- An **Admin** or **Business Manager** account is created
- All steps on the **Go Live** page are completed

If you do not have an admin account, contact the onboarding team at:
**m-pesabusiness@safaricom.co.ke**

## M-Pesa API Certificates

Safaricom provides public key certificates used to encrypt sensitive security credentials.

### Available Certificates
- **Sandbox Public Key Certificate**
- **Production Public Key Certificate**

### Usage
These certificates are required for:
- B2C
- B2B
- Transaction Status Query
- Reversal APIs

> Note: These certificates are **not** used to access the M-PESA Organization Portal.

---

## Generating Security Credentials

M-Pesa Core validates transactions by decrypting security credentials generated using Safaricom’s public key.

### Credential Generation Algorithm
1. Write the initiator password into a byte array.
2. Encrypt the byte array using:
   - RSA algorithm
   - PKCS #1.5 padding (OAEP is not supported)
3. Base64-encode the encrypted byte array.
4. Use the resulting string as the **Security Credential**.

> Important: Always use the correct certificate for your environment (Sandbox or Production).

## Creating an HTTP Server

M-Pesa APIs are **asynchronous**. Responses are sent to:
- `CallBackURL`
- `ResultURL`

If the server is unavailable, the API Gateway returns a **503 error** and discards the response.

### Requirements
- Deploy an HTTP server that accepts POST requests
- Ensure high availability
- Use Ngrok or LocalTunnel during local testing

Sample listeners and response handlers are provided in:
- Python
- NodeJS
- PHP
- Java
