# Introduction to APIs — Summary

## 1. The Basic Anatomy of an API Request
Fetching data from an API is simple, but to interact with APIs more precisely, we use the **Python `requests` package**. This package allows us to send detailed instructions along with our API requests, such as parameters and data payloads.

---

## 2. What Are URLs?
A **URL (Uniform Resource Locator)** is a structured address that points to a specific resource on the web.  
In the context of Web APIs, a URL defines **which resource we want to interact with**.

**Analogy:**  
A REST API is like an office building:
- Each office unit represents a **unique resource**
- The URL is the **address of a specific office unit**
- The URL contains all the information needed to reach that resource

---

## 3. Dissecting a URL
A URL is composed of **five main components**:

1. **Protocol**  
   Determines how data is transported (e.g., like walking vs. driving).
   
2. **Domain**  
   Comparable to the street address of the building.  
   It uniquely identifies the API server on the internet.

3. **Port**  
   Acts as the gateway or entrance into the building.  
   Common default ports:
   - `80` (HTTP)
   - `443` (HTTPS)

4. **Path**  
   Specifies the exact resource on the server.  
   Each API resource has a unique path.

5. **Query**  
   Provides additional instructions, similar to directions like “take the elevator.”  
   By combining paths and query parameters, we control where and how API requests are handled.

---

## 4. Adding Query Parameters with `requests`
Query parameters can be added directly to a URL string, but there is a **better and cleaner approach**.

The `requests` package allows you to pass query parameters using the `params` argument:
- `params` accepts a dictionary of key/value pairs
- Each pair represents one query parameter
- This approach is easier to read and maintain

---

## 5. HTTP Verbs
Once a request reaches its destination, **HTTP verbs** define what action should be performed.

Although there are **9 HTTP verbs**, simple REST APIs typically use these four:

- **GET** — Read a resource  
  (Checking the mailbox without removing anything)

- **POST** — Create a resource  
  (Dropping a new package into the mailbox)

- **PUT** — Update a resource  
  (Replacing an existing package)

- **DELETE** — Remove a resource  
  (Emptying the mailbox)

---

## 6. Sending Data via POST and PUT
The `requests` package provides functions for each HTTP verb:

- `requests.get()`
- `requests.post()`
- `requests.put()`
- `requests.delete()`

For **POST** and **PUT** requests:
- Data must be sent to create or update resources
- This data is passed using the `data` argument, similar to how `params` is used for query parameters

DELETE requests are simpler and only require calling the `delete` function.
