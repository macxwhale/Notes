# Introduction to APIs — Core Concepts

## 1. The Basic Anatomy of an API Request

Fetching data from an API is straightforward, but more advanced interactions require giving the API detailed instructions. In Python, this is commonly done using the `requests` package, which allows you to control how requests are sent and what information they include.

---

## 2. What Are URLs?

URLs (Uniform Resource Locators) are a fundamental concept in Web APIs. A URL is a structured address that points to a specific resource on the web.

A useful analogy is a REST API as an office building:

* Each office unit represents a **unique resource**
* The URL is the **address of a single office unit**

The URL contains all the information needed to locate and interact with that specific resource.

---

## 3. Dissecting a URL

A URL consists of five main components:

1. **Protocol**
   Determines how data is transported to the destination (e.g., walking vs driving).
   Common examples: `http`, `https`.

2. **Domain**
   The street address of the office building.
   It uniquely identifies the API server on the internet.

3. **Port**
   The gateway or entrance into the building.
   Common default ports:

   * `80` for HTTP
   * `443` for HTTPS

4. **Path**
   Identifies the specific resource (office unit) within the server.
   Each API resource has a unique path.

5. **Query**
   Contains additional instructions for the request.
   Similar to directions like “take the elevator.”
   By combining paths and query parameters, you precisely control where and how API requests are sent.

---

## 4. Adding Query Parameters with `requests`

Query parameters can be added directly to a URL string, but there is a better and cleaner approach.

The `requests` package allows query parameters to be passed using the `params` argument:

* `params` accepts a dictionary
* Each key/value pair represents a query parameter

This method improves readability and reduces errors compared to manual URL construction.

---

## 5. HTTP Verbs

HTTP verbs define **what action** should be performed on a resource once the request reaches its destination.

Although there are **9 HTTP verbs in total**, most REST APIs rely on four core ones:

* **GET**
  Reads a resource
  (Like checking what’s in a mailbox without removing anything)

* **POST**
  Creates a new resource
  (Like placing a new package into a mailbox)

* **PUT**
  Updates an existing resource
  (Like replacing a package already in the mailbox)

* **DELETE**
  Removes a resource
  (Like emptying the mailbox completely)

These four verbs are sufficient for most simple REST APIs.

---

## 6. Sending Data via POST and PUT

The `requests` package provides functions for all HTTP verbs:

* `requests.get()`
* `requests.post()`
* `requests.put()`
* `requests.delete()`

For **POST** and **PUT** requests:

* Data must be sent to create or update resources
* This is done using the `data` argument, similar in concept to the `params` argument for query parameters

DELETE requests are simpler and only require calling `requests.delete()`.
