# AWS Cloud Practitioner Essentials – VPC Networking Demo Summary

## Overview

This demo walks through how to set up core networking components in AWS using the AWS Management Console. The goal is to understand how a Virtual Private Cloud (VPC) and its related resources work together in practice.

---

## 1. Creating a VPC

* A **Virtual Private Cloud (VPC)** is the foundational network where AWS resources are launched.
* Steps:

  * Navigate to VPC service → **Create VPC**
  * Select **VPC Only**
  * Assign a name (e.g., `My VPC`)
  * Define a **CIDR block** (e.g., `10.0.0.0/16`)

    * CIDR defines the range of private IP addresses available in the VPC
* Result:

  * All resources in the VPC receive private IPs within this range

---

## 2. Creating Subnets

### Key Concept:

* A **subnet** is a smaller range of IP addresses within a VPC
* Types:

  * **Public subnet** → internet-accessible resources
  * **Private subnet** → internal-only resources

### Best Practice:

* Create subnets across **multiple Availability Zones (AZs)** for **high availability**

### Private Subnets:

* Example configurations:

  * `Private-subnet-1` → AZ: `us-east-1a`, CIDR: `10.0.1.0/24`
  * `Private-subnet-2` → Different AZ, CIDR: `10.0.2.0/24`
* Important setting:

  * **Disable auto-assign public IP**

### Public Subnets:

* Example configurations:

  * `Public-subnet-1` → AZ: `us-east-1a`, CIDR: `10.0.3.0/24`
  * `Public-subnet-2` → Different AZ, CIDR: `10.0.4.0/24`
* Important setting:

  * **Enable auto-assign public IP**

### Result:

* 4 subnets total:

  * 2 public + 2 private
  * Distributed across 2 AZs

---

## 3. Internet Gateway (IGW)

* Enables communication between the VPC and the internet

### Steps:

* Create an internet gateway (e.g., `my-ig`)
* Attach it to the VPC

### Key Point:

* Subnets are not public **until routing is configured**, even if labeled “public”

---

## 4. Route Tables

### Definition:

* A **route table** contains rules (routes) that determine how network traffic is directed

### Steps:

1. Create a route table (e.g., `public-route-table`)
2. Add a route:

   * Destination: `0.0.0.0/0` (all internet traffic)
   * Target: Internet Gateway
3. Associate route table with:

   * `Public-subnet-1`
   * `Public-subnet-2`

### Result:

* Public subnets gain internet access
* Private subnets remain isolated (no IGW route)

---

## 5. Traffic Control & Security

* Traffic into and out of the VPC is controlled by:

  * **Security Groups**
  * **Network Access Control Lists (NACLs)**

### Key Point:

* Both use **CIDR blocks** to define allowed traffic sources and destinations

---

## 6. Core Architecture Summary

The demo builds:

* 1 VPC
* 4 Subnets:

  * 2 Public
  * 2 Private
* 1 Internet Gateway
* 1 Route Table for public traffic

---

## 7. Key Takeaways

* A VPC must be created before launching AWS resources
* Subnets should span multiple AZs for high availability
* Internet access requires:

  * Internet Gateway
  * Proper route table configuration
* Subnets are only “public” when routing allows internet access
* Security groups and NACLs control traffic flow
